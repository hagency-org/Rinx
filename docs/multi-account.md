# 多账号登录与切换

## 产品行为

Rinx 保存多个 Matrix 账号的登录会话，一次只激活一个账号。可以登录同一服务器的不同账号，也可以登录不同服务器的账号。身份由完整 Matrix 用户 ID（包含服务器名）确定。每个账号保留自己的 Matrix 设备和加密数据库；切换不调用服务器 logout。

入口：

- 桌面左下角账号菜单：当前账号头像／名称／ID、已登录账号列表、添加账号、账号设置、退出登录。
- 手机端“我 → 设置 → 账号”：使用同一个账号列表和添加按钮，避免两套流程不一致。
- 登录页：显示已保存账号。添加失败或取消后，可以直接选择原账号返回。

列表以完整用户 ID 区分账号；当前账号标记“Active／当前”，不可重复选择。超过四个账号时列表可滚动。首版不让未激活账号在后台同步，因此不汇总它们的未读数或推送通知。

## 添加与切换流程

添加：保存当前账号界面状态 → 暂停并清理当前活动会话 → 显示既有登录页 → 使用服务器支持的密码或浏览器 SSO 登录 → 安全保存新会话 → 启动新账号同步。原账号会话和密钥保留；登录失败不会删除原账号。

切换：点击已保存账号 → 显示切换状态并阻止重复操作／发送 → 停止原账号 SDK 发送队列和同步 → 关闭账号任务作用域并等待取消完成 → 清除 worker 订阅及下载记录 → 撤销小应用与助手权限上下文 → 清空账号相关界面及缓存 → 等待 UI 完整处理清理事件 → 恢复目标账号会话和自己的界面状态 → 同步。

退出：沿用退出确认与服务器撤销流程，只移除当前账号的 token 文件。其他账号仍可选择；当前账号的加密数据库保留为本地恢复材料，恢复材料不含 access token 或 refresh token。重新进入账号需要登录。退出失败时保持现有错误反馈，不谎报成功。

会话失效：清理活动状态，回到登录页，允许重新登录或选择另一个账号。密码重新认证复用该账号原来的数据库和设备 ID。重复 SSO 登录优先恢复仍有效的原设备；失效后的 SSO 可能发放新设备，旧数据库仍保留，历史消息恢复取决于 Matrix 密钥备份／设备验证。

## 本地数据边界

| 数据 | 隔离方式 |
| --- | --- |
| 用户身份 | 完整 Matrix ID；目录名为完整 ID 的 BLAKE3 摘要，避免旧的字符替换碰撞及路径字符问题 |
| access／refresh token、SDK 数据库路径及密码 | `account_<digest>/persistent_state/session`；原子替换，Unix 文件 0600，账号目录 0700；账号列表内存仅保存 ID 与服务器地址 |
| Matrix 消息、事件缓存、加密密钥 | 每个登录设备独立的随机命名 SQLite 数据库及 SDK 缓存；切换恢复同一数据库；退出恢复索引保留原数据库 |
| 选中聊天、标签布局、设置、权限发现状态 | 该账号 `persistent_state/latest_app_state.json`；保存后清理，目标账号独立恢复 |
| 小应用状态／授权、阅读器标签、助手房间授权 | 沿用已有完整账号键／摘要隔离；切换撤销旧 lease 和等待中的授权结果 |
| 头像、用户资料、房间预览、时间线、下载和订阅 | 取消旧任务后清理缓存、待处理更新队列与 widget 状态；不会复用原账号房间标签 |
| 原生文件选择器结果 | 在打开时捕获会话代次；完成结果也携带代次，切换后丢弃旧结果 |
| 分享临时文件 | `cache/temp/<account digest>/…`；后台分享开始前捕获所属账号目录 |
| 语言、窗口位置、主题包、程序运行配置 | 应用级配置，账号之间共享 |

目录隔离用于防止应用内账号串数据，不是同一操作系统用户下的密码学保密边界。现有 session 文件中包含数据库密码，暂未接入系统钥匙串；不把 token 写入账号索引或测试报告。

## 兼容与恢复

启动先扫描 session 文件，核对文件中的真实用户 ID，再把旧 `<user_server>/persistent_state` 所在目录移动到新的账号目录；原会话字节、设备 ID、界面文件和数据库路径不变。迁移可以重复执行。已有新目录时不会覆盖；错误或权限失败会报告，并跳过数据库清理。读取目标会话还会核对用户 ID，拒绝错放文件。

数据库清理扫描全部已保存账号及不含 token 的 `retained_db.json` 恢复索引；读取失败或格式损坏时停止清理。不会因为另一个账号不是最近使用的账号而删除它的数据库。

实验性 `tsp` 构建的独立钱包服务仍使用进程级身份状态，本次明确拒绝切换，避免把钱包带入另一个 Matrix 账号。默认构建未启用此功能。TSP 需要另行实现钱包迁移、请求代次及接收循环边界，才能开启多账号。

## 验证

新增单元测试覆盖完整 ID 路径碰撞、历史目录迁移及幂等、错误归属会话拒绝、已有目录保护、只删除指定账号会话、后台任务取消及重新开放作用域。

`tools/wechat-ux/live/native_multi_account.py` 使用隔离的 loopback Matrix HTTP 服务、真实 Rinx 原生界面和 Matrix SDK 验证添加失败恢复、两账号独立 session／数据库、A→B→A 切换、切换不重复密码登录或服务器退出、只退出当前账号、设置页入口、重启恢复账号。原生 fixture 已通过全部六项流程检查，库测试 340 项通过、2 项忽略；默认构建及无默认特性检查、i18n 与主题检查通过。它不替代真实 homeserver、端到端加密互通、手机真机或推送通知验收。
